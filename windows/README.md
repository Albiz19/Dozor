# Dozor для Windows 10 и 11 · прототип

Консольная утилита x64 устанавливает правила Windows Filtering Platform (WFP) для явно указанных файлов `.exe`. В режиме `guard` Windows должна разрешать новые исходящие подключения выбранной программы только при совпадении интерфейса локального адреса и интерфейса следующего перехода с указанным VPN. Если одно из условий неизвестно, остаётся правило блокировки. Для IPv4 и IPv6 используются отдельные правила на уровнях ALE_AUTH_CONNECT. [Условия фильтрации Microsoft](https://learn.microsoft.com/en-us/windows/win32/fwp/filtering-conditions-available-at-each-filtering-layer)

## Сборка и запуск

Установите Visual Studio Build Tools 2022 с компонентами C++ для desktop, Windows SDK и CMake. В Developer PowerShell из корня репозитория выполните:

```powershell
cmake -S windows -B build -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Первую проверку проводите в тестовой Windows с отдельной программой. Откройте PowerShell от имени администратора. Подключите VPN и найдите GUID его виртуального адаптера. Сверьте GUID с адаптером вашего VPN. Само наличие виртуального адаптера не подтверждает шифрование или страну выхода.

```powershell
Get-NetAdapter -IncludeHidden | Format-Table Name, InterfaceDescription, Status, InterfaceGuid
$dozor = (Resolve-Path .\build\Release\dozor-win.exe).Path
$testApp = 'C:\Lab\my-test-client.exe'   # полный путь к существующему .exe
& $dozor lock $testApp
& $dozor guard '{GUID-ВАШЕГО-VPN}' $testApp
```

Команда `lock` блокирует выбранную программу на всех интерфейсах. Команда `guard` сама сначала устанавливает эту блокировку. Только после проверки работающего виртуального адаптера она открывает временные разрешения. Фильтры сравнивают LUID интерфейса во время авторизации соединения. Изменение IPv4 и IPv6 для всех указанных программ происходит одной транзакцией. Утилита принимает несколько путей через пробел. Указывайте путь каждого отдельного сетевого помощника.

Оставьте окно `guard` открытым. При выходе по Ctrl+C или завершении процесса Windows удаляет его временные разрешения. Постоянные запреты остаются. Команда `guard` завершится с ошибкой, если VPN выключен при запуске. После восстановления подключения запустите её снова. Для полного снятия запрета сначала завершите `guard`, затем выполните:

```powershell
& $dozor unlock $testApp
```

Снимайте запрет **до** перемещения или удаления программы. Команда разрешает путь через существующий файл. Если программа уже удалена, восстановите файл на прежний путь и повторите команду. Пока `guard` активен, другой экземпляр утилиты не меняет политику. [Время жизни правил WFP](https://learn.microsoft.com/en-us/windows/win32/fwp/object-management)

## Что проверяется

Переносимый тест перебирает 36 комбинаций IPv4/IPv6, работающей/закрытой сессии и известных/неизвестных интерфейсов локального адреса и следующего перехода. Его можно собрать на macOS командой `clang++ -std=c++17 windows/tests/policy.cpp -o /tmp/dozor-policy` и запустить `/tmp/dozor-policy`.

Для Windows подготовлен второй тест. Он создаёт отдельный временный EXE и серверы на 127.0.0.1 и ::1, проверяет успешное подключение, запрет с ошибкой доступа и восстановление. Дополнительно проверяет повторный `lock`, исчезнувший адаптер и откат частичного `unlock`. Запускайте в одноразовой VM от администратора. Тест затрагивает только созданный EXE.

```powershell
.\windows\tests\loopback.ps1 -Dozor (Resolve-Path .\build\Release\dozor-win.exe)
```

На целевых Windows 10 и 11 отдельно требуется проверить успешную связь через реальный туннель, смену маршрута у открытого TCP-соединения, длительный UDP-поток, поведение при остановке VPN и принудительном завершении Dozor. Для подтверждения отсутствия утечки нужен перехват на внешнем интерфейсе в изолированном стенде. CI Windows Server собирает проект и запускает тест правил и локальный TCP-сценарий.

## Границы прототипа

- Правило применяется по идентификатору исполняемого файла WFP. Дочерний процесс с другим EXE, системная служба DNS, WSL, прокси или приложение в виртуальной машине имеют отдельную идентичность. Установка запрета на общий интерпретатор затронет все приложения, использующие тот же файл. [Идентификатор приложения](https://learn.microsoft.com/en-us/windows/win32/api/fwpmu/nf-fwpmu-fwpmgetappidfromfilename0)
- WFP авторизует соединения и повторно проверяет их при некоторых изменениях. Это не даёт измеренной гарантии для каждого пакета ранее открытого сокета. Функции контроля внешнего IP, диагностики DNS, автозапуска, Telegram и графического интерфейса пока доступны только в macOS-версии в объёме, описанном в основном README. [Модель ALE](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-stateful-filtering)
- До запуска Base Filtering Engine постоянные фильтры этого прототипа не обеспечивают загрузочную блокировку. Соседние политики WFP могут влиять на результат, а выбранный VPN должен иметь собственный виртуальный адаптер. Работа только через локальный HTTP/SOCKS-прокси этим режимом не поддерживается. [Арбитраж фильтров](https://learn.microsoft.com/en-us/windows/win32/fwp/filter-arbitration)
