# Выпуск обновления

`VERSION` определяет отображаемую версию пакета, расширения и архива. Выпускайте стабильные теги вида `v0.1` или `v0.1.1`. Новая версия должна быть численно больше предыдущей. Увеличьте также `BUILD_NUMBER` в `build.sh` для нового выпуска системного расширения.

1. Обновите `VERSION` и `CHANGELOG.md`. Соберите `./build.sh`, выполните `python3 tests/run.py`. Для релиза с системной подписью передайте профили и идентификатор сертификата сборщику. Для широкой раздачи подписанного варианта отдельно выполните нотарификацию и прикрепите ticket перед упаковкой.
2. Запустите `python3 scripts/package-release.py`. Скрипт сверяет версии обоих пакетов, проверяет подпись, создаёт ZIP, `dist/SHA256SUMS` и обновляет `Casks/dozor.rb` хешем именно этого архива.
3. Закоммитьте исходники и cask, поставьте тег на этот коммит. Отправьте ветку и тег. Создайте релиз через GitHub Releases, приложите полученный ZIP и `SHA256SUMS`. Для стабильной версии выберите **Set as the latest release**. Не заменяйте ZIP после публикации под тем же тегом.
4. Проверьте публичный URL скачивания, контрольную сумму и результат `gh api repos/Albiz19/Dozor/releases/latest --jq .tag_name`. Проверка из приложения использует этот endpoint. Для проверки Homebrew выполните `brew update`, затем `brew fetch --cask albiz19/dozor/dozor` из подключённого tap после явного доверия этому cask (`brew trust --cask albiz19/dozor/dozor`).

ZIP и бинарники распространяются как вложения выпуска. Настройки пользователя и профили подписи не входят в репозиторий.
