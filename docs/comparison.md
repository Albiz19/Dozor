# Что Dozor может перенять у 13 проектов

Обзор от 13 ноября 2026 года. Сравнивались документация разработчиков и описания архитектуры в официальных репозиториях. Приложения конкурентов не устанавливали, VPN не отключали. «Заявлено» ниже означает описание авторов, а не независимо измеренный результат. Нельзя по этой таблице ранжировать время блокировки или обещать, что одна реализация безопаснее другой.

## Где именно блокируется трафик

| Проект и первоисточник | Что умеет и где принимает решение | Что это означает для Dozor |
|---|---|---|
| [Kordon](https://github.com/ef1m03/kordon), [модель безопасности](https://github.com/ef1m03/kordon/blob/main/SECURITY.md) | Ближайший аналог: выбранные пользовательские процессы ставятся на паузу. Слушает изменения сети и периодически сверяет внешний IP. Авторы описывают заморозку перед сном, свежую проверку после пробуждения и отдельный сторожевой процесс на случай падения основной программы. | Нужны разные испытания: VPN пропал, наблюдатель завершился, компьютер проснулся. Сигнал процессу не отзывает данные, уже переданные ядру. Сторож сокращает окно после падения, но не превращает паузу в сетевой фильтр. |
| [Mullvad](https://mullvad.net/en/help/using-mullvad-vpn-app) | VPN-клиент различает обрыв соединения и сознательное отключение. Lockdown оставляет интернет закрытым и после выхода. Split tunneling выводит выбранные приложения за пределы туннеля. | Статусы «VPN подключён» и «данное приложение обязано идти в туннель» независимы. При ручном отключении VPN выбранные процессы Dozor должны остаться в заморозке. |
| [Proton VPN](https://protonvpn.com/support/what-is-kill-switch) | Обычный kill switch реагирует на непредвиденный разрыв. Advanced, где он поддерживается, также запрещает доступ после ручного отключения и перезагрузки. Заявленная поддержка режимов различается по ОС. | Один и тот же зелёный индикатор на macOS и Windows не должен обещать одинаковых гарантий. Указать, что сохраняется после перезагрузки и до входа пользователя. |
| [IVPN](https://github.com/ivpn/desktop-app), [пределы защиты при загрузке](https://updates.ivpn.net/knowledgebase/general/do-you-offer-a-kill-switch-or-vpn-firewall/) | Привилегированная служба, интерфейс и CLI разделены. Межсетевой экран ограничивает выход вне туннеля; для начальной стадии загрузки авторы отдельно оговаривают ограничения macOS и Linux. | Проверять состояние исполнителя правил независимо от того, открыт ли интерфейс. Поведение до запуска Dozor — отдельное условие приёмки, которое нельзя вывести из теста кнопки «Включить». |
| [Windscribe Firewall](https://windscribe.com/features/firewall) | Различает автоматический, ручной и постоянный запрет. В описании явно разделены штатный выход, авария клиента и рестарт компьютера. Политика постоянного режима ставится до обрыва. | Не ждать события для установки первого запрета. В режиме заморозки Dozor событие необходимо; для строгого режима нужен уже действующий системный барьер. |
| [Little Snitch](https://obdev.at/products/littlesnitch/index.html) | На macOS показывает приложение, назначение, порт, протокол; принимает решения по соединениям. В тихом режиме возможен первоначальный пропуск. | В диагностике показывать, какое правило объясняет решение. Тихий сбор статистики с разрешающим первым запросом несовместим со строгой защитой. |
| [LuLu](https://objective-see.org/products/lulu.html) | Исходящий межсетевой экран macOS со сменными профилями. Документация оговаривает приоритет списков и ограничения правил по имени узла для приложений, не использующих определённые API Apple. | Нельзя полагаться на имя домена как на границу защиты. Проверять выбор приложения и транспорт даже тогда, когда имя удалённого узла неизвестно. |
| [OpenSnitch](https://github.com/evilsocket/opensnitch) | Linux: интерактивное принятие решений по исходящим соединениям и управление системными правилами nftables через GUI. Объекты правил и события доступны для расследования. | Отделить решение по конкретному потоку от общего состояния системы; в диагностике указать, вызван ли отказ проверкой адреса, отсутствием туннеля или сетевым правилом. |
| [simplewall](https://github.com/henrypp/simplewall) | Windows: настраивает фильтры WFP, различает постоянные и временные правила. Это не оболочка для управления Microsoft Defender Firewall. | Для Windows явно указать выбранный API и срок жизни правил. Отдельно испытать закрытие интерфейса, рестарт и удаление только собственных правил. |
| [Portmaster](https://github.com/safing/portmaster) | Раздельная атрибуция соединений процессам, политики localhost/LAN/Internet и обработка DNS. На Windows авторы используют драйвер и IP Helper API; предусмотрен локальный журнал соединений. | Адрес назначения и владелец сокета — разные доказательства. Системный DNS-посредник или общий прокси могут иметь другого владельца; адрес, увиденный при HTTPS-проверке, не проверяет их путь. |
| [Tailscale exit nodes](https://tailscale.com/docs/features/exit-nodes) | По умолчанию оверлей соединяет участников сети, но не меняет маршрут обычного интернета. | [WireGuard: network namespaces](https://www.wireguard.com/netns/) | На Linux сетевое пространство процесса может содержать только интерфейс WireGuard, а физический интерфейс остаётся в другом пространстве. Linux namespaces не являются готовой реализацией для macOS или Windows. |
| [Gluetun](https://github.com/qdm12/gluetun) | VPN-клиент в контейнере с собственным сетевым экраном и DNS. Контейнер не контролирует произвольные приложения хоста. |

## Что имеет смысл реализовать

Приоритет определён последствиями отказа, а не количеством похожих функций у конкурентов. Это критерии для реализации и испытаний, не список уже выполненных работ.

| Приоритет | Изменение | Приёмка |
|---|---|---|
| P0 | Не размораживать по устаревшему подтверждению. Инвалидировать его при изменении пути, сна, настроек, смене исполнителя туннеля. | Старый успешный ответ приходит после нового поколения сети; истекает срок проверки; туннель меняется между двумя процессами. В каждом случае следующий процесс не получает сигнал продолжения. После восстановления требуется новая проверка. |
| P0 | Различать отсутствие IPv6 и доступный IPv6 с непроверенным выходом. Ошибка проверки доступного пути не должна означать «пути нет». | При разрешённом IPv4 и наличии непроверенного публичного пути IPv6 решение остаётся запрещающим. Отдельный положительный сценарий — действительно недоступный IPv6. |
| P0 | Для обещания блокировать пакеты — системное принуждение до первого соединения; для режима заморозки — явная надпись о его пределах. | В изолированной системе измерить новые и ранее открытые потоки, TCP и UDP, обе семьи, системный DNS, родителей и потомков до и после смены сети. Наблюдать внешний интерфейс отдельным приёмником. Тест решения в памяти не заменяет это измерение. |
| P1 | Разделить «проверка начата», «получен отказ», «доказательство просрочено», «фильтр отсутствует»; показывать причину без записи заголовков, прокси-паролей или Telegram-токенов. | Ответ 407 или тайм-аут не отображается как вечная проверка. Состояние после успешного нового раунда объясняет, почему блокировка снята. |
| P1 | На Windows ограничить правила выбранными путями программ и задать предсказуемую очистку. | На чистых Windows 10 и 11 проверить маршрут по IPv4/IPv6, новый адаптер, потомка с другим путём, удаление правил и сохранность чужих правил. Прототип без этих испытаний помечать экспериментальным. |
| P2 | Решить отдельно судьбу трафика до входа, при падении контроллера и при обновлении. | На одноразовом хосте остановить только тестовый контроллер, проверить состояние системного правила и восстановление. Оповещение Telegram не должно быть причиной снятия запрета или условием восстановления. |

Главная разница: проба сообщает, каким путём прошёл **один запрос**. Из неё нельзя вывести маршрут всех открытых сокетов, DNS, UDP или будущего дочернего процесса. Даже несколько удачных проб не заменяют правила, которое ОС применяет к самому трафику. Страну по базе GeoIP можно показывать справочно; решение о защите и утверждение об отсутствии сетевой утечки требуют других доказательств.

Для кандидата 0.4 [таблица реализованных функций](features-0.4.md) указывает источники, путь к каждой настройке и её действие.
