# Результаты проверки кандидата 0.3.0

Задача: выяснить, может ли Dozor разрешить выбранной программе работать без свежего подтверждения VPN, и измерить результат отдельно для заморозки и правил сокетов. В испытаниях использованы три одноразовых процесса, отдельный каталог состояния, фиктивные таблицы маршрутов и сетевые приёмники loopback. Пользовательский VPN и рабочие приложения в испытания не входили.

| Проблема | Исправление и результат |
|---|---|
| При пустом реестре и работающем локальном прокси новый процесс мог получить положительное решение без подтверждённого VPN. | Требуем VPN и при первом решении. Только локальный слушатель вместе со всеми положительными IP-пробами не разрешил защищённый запуск. |
| Неоднозначная или недоступная таблица маршрутов IPv6 могла интерпретироваться как отсутствие IPv6. | Различаются отсутствие, конкретный интерфейс и ошибка. Проведены тесты неполной таблицы, двух интерфейсов, выхода IPv6 без основного маршрута и смены интерфейса в процессе проверки. |
| Ответ, пришедший в переходном состоянии, мог быть неверно привязан к соединению. | Для системного VPN проверяются оба конца раунда. Для incy сверяется идентичность TUN. Перед каждым продолжением проверяется срок по двум часам; сон отзывает разрешение. Истёкший раунд и смена туннеля между двумя сигналами протестированы. |
| Два сервиса могли перенаправить запрос к одному свидетелю; адрес с некорректным окончанием мог частично разобрать C-парсер. | Редиректы не принимаются, имена источников нормализуются, некорректные IP и префиксы отклоняются. В тесте HTTP-сервер видел запрос перенаправления и независимый контрольный запрос, но не запрос по перенаправлению. |
| Постороннее дерево могло быть связано с повторно использованным PID родителя. | При обходе сверяется экземпляр родителя, включая время запуска. Проверки хранения, возобновления и устаревшей идентичности используют известные тестовые PID. |

**macOS.** Полная локальная серия — 107 результатов PASS. В неё входят проверки принятия решений, системных сигналов, Telegram на подменном API, сравнения версий, политики фильтра и сокетов. После подтверждённого STOP независимый UDP-приёмник не получил данных от родителя, ребёнка и внука в проверках удержания. До остановки и после свежего разрешения он получил три разных метки. Отдельно для dozor-run: 3 положительных проксированных контроля, 36 прямых TCP/UDP попыток по IPv4/IPv6 и 0 доставок. Отсчёт при заморозке начинается **после** подтверждённой остановки; это не измерение интервала до обнаружения обрыва. [Прогон CI](https://github.com/Albiz19/Dozor/actions/runs/43502675819).

**Windows.** 36 комбинаций правил проверены отдельно от интеграционного сценария. [На Windows Server 2022](https://github.com/Albiz19/Dozor/actions/runs/43502512702) собраны Debug и Release. С настоящим WFP и тестовым EXE проверены блокировка TCP/UDP IPv4/IPv6, положительный контроль по loopback, отзыв временного разрешения при аварийном завершении контроллера, неверный GUID и откат транзакции. Разрешение loopback доступно только специальной тестовой сборке, в выпуск вложена обычная.

**До объявления стабильной версии.** Необходимо испытать подписанный и разрешённый macOS Network Extension на отдельном Mac и связку Windows 10/11 с реальным адаптером VPN. В изолированной сети нужны наблюдение на физическом интерфейсе, старые и новые потоки, UDP/QUIC, системный DNS, быстрая смена маршрутов, смена адаптера, потеря питания и перезагрузка. На Windows правила относятся к указанным EXE, не к произвольным потомкам. На macOS заморозка может опоздать; локальный прокси и его транспорт тоже требуют собственной политики. До этих испытаний вывод «ни одного пакета мимо VPN» не подтверждён. Существующий стабильный релиз и локальная установка остаются без изменений.
